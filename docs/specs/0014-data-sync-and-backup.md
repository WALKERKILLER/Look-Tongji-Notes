# Data sync and backup

Artifact-Version: 1
Status: Approved

## Intent

Students use Look Studio on more than one device (a desktop, a laptop, an Android phone) and reinstall systems. They want the same library and assistant history everywhere without a Look Studio server, and a file they can keep as a backup. Scope of this contract: a two-way sync of the library and the assistant's portable data through a WebDAV folder the user owns, backup archives to export and restore, and a storage overview with safe cleanup. Non-goals: syncing credentials, login state or device settings; end-to-end encryption of the WebDAV folder; real-time collaboration; merging two edits of the same note line by line.

Constraints: files stay the source of truth and the index can always be rebuilt from them; nothing the user wrote is lost silently (a replaced or deleted copy is kept); credentials stay inside lookd, sealed with the device key.

## Contract

- **Data set.** Archive paths are `library/<path>` and `data/<path>`. `library/` is every file under the library root except `library.db*`, hidden folders (`.cache`, `.mirror-journal`, `.sync-conflicts`, `.sync-trash`) and partial downloads (`*.part`, `*.tmp`, `*.moving`); videos and recordings (by extension) only when the user opts in. `data/` is an allowlist of the assistant's data: `agent/assistant.json`, `agent/sessions-meta.json`, `agent/tasks.json`, `agent/tasks-runs.jsonl`, `agent/usage.jsonl`, `agent/sessions/**`, `agent/bot/**`. Keys, sessions, sealed tokens, `seal.key`, model configuration, plugins and caches never leave the device. Paths outside the set, absolute or containing `..`, are rejected on the way in.
- **Index state.** Playback positions and bookmarks live only in `library.db`; they travel as `state/library.json` (`store.UserState`) and merge record by record: the newer position per lecture, bookmarks the index lacks (deleting a bookmark does not propagate). After files arrive, `Reindex` adopts courses, lectures, their folders, local files and slides from `course.json`, `lecture.json` and `slides/index.json`, and drops notes whose file is gone, so a copied library shows its lectures as downloaded before the user signs in.
- **Backup.** `GET /api/data/estimate` → `{files, bytes, media_files, media_bytes}`. `GET /api/data/export[?media=1]` streams a zip: `manifest.json` (`{format: "look-studio-backup", version: 1, created, device, app, media, files{path: {size, mtime}}}`), `state/library.json`, then the files with their modification times (images and media stored, text deflated). `POST /api/data/import` takes the zip as the raw body, keeps it in `<data>/imports/` (removed after a day) and returns a preview `{id, created, device, app, media, files, bytes, new, newer, older, same, skipped, state}`; a file that is not a backup → 400. `POST /api/data/import/{id}/apply {mode}`: `merge` writes files that are missing or newer in the backup; `overwrite` writes every differing file and first copies newer local files to `.sync-conflicts/<time>-restore/` (assistant data under `data/`). Returns `{written, kept, bytes, library, data, conflict?}`. `DELETE /api/data/import/{id}` discards.
- **WebDAV.** `PUT /api/sync {url, user, password?, folder, auto, media}` checks the account (PROPFIND depth 0) and creates the folder (MKCOL) before saving; the password is sealed in `<data>/sync.json` and never returned (`has_password`). Changing the address, account or folder forgets what was agreed with the old folder. `GET /api/sync` → `{configured, url, user, has_password, folder, auto, media, device, files, running, progress{step, done, total, bytes}?, last{at, uploaded, downloaded, deleted, conflicts, bytes, conflict_dir?, errors[], error?, partial?}?}`. `POST /api/sync/run` starts a sync in the background (409 when not configured), `POST /api/sync/auto {auto}`, `DELETE /api/sync` forgets the account; files on both sides stay. SSE: `sync_progress`, `sync_done <result>`, `sync_changed`.
- **Remote layout.** `<folder>/manifest.json` `{format: "look-studio-sync", version: 1, updated, device, state{size, mtime, sha256}, files{path: {size, mtime, sha256} | {mtime, deleted}}}`, `<folder>/files/<archive path>`, `<folder>/state/library.json`. Tombstones are kept for 90 days.
- **Sync rules.** Each device keeps the base, the version it last agreed with the remote, per path. A path that differs only locally is uploaded (or tombstoned when deleted); one that differs only remotely is downloaded (or moved to `.sync-trash/<time>/` when deleted remotely); when both changed, an edit beats a deletion, append-only logs (`data/**/*.jsonl`) keep the lines of both, and otherwise the newer modification wins while the other copy goes to `.sync-conflicts/<time>/` (assistant data under `data/` in the conflict and trash folders; generated `lecture.json`, `course.json`, `slides/index.json` and the library README just take the newer copy). Downloads are verified against the manifest's SHA-256 and replace files atomically with the remote modification time. Uploads count as agreed only after the manifest is written with `If-Match` on the ETag read at the start; a 412 restarts the run (three tries). Authentication, permission, rate-limit (429/503) and quota errors stop the run and keep finished transfers (`partial`); other per-file errors are listed and retried next time. Four transfers run in parallel. Local hashes are cached by size and modification time in `<data>/sync-cache.json`. Media stay out unless enabled; turning media off forgets their base entries so they are never read as deletions.
- **Automatic sync.** With `auto`: 20 s after start, every 30 minutes, and about 2 minutes after notes change (bursts coalesce). After files arrive lookd reindexes the library, publishes the refresh events pages already listen to, and restarts the assistant when its data changed.
- **Storage.** `GET /api/storage` → `{library, total, categories[{key, label, bytes, files}], cleanable{cache, sync, index}, models, assistant, runtime}` with categories video, slides, courseware, text, index, cache, sync, other. `POST /api/storage/clean {cache?, sync?, compact?}` → `{freed}`: `cache` removes `.cache` entries of lectures without a queued, running or paused job (transcription chunk folders only when no transcription runs or after six hours); `sync` empties `.sync-conflicts` and `.sync-trash`; `compact` checkpoints the WAL and runs `VACUUM`.
- **App.** 设置 → 数据与同步: a WebDAV entry with status (presets for 坚果云, Nextcloud, AList and others, the connect form, automatic sync, media, progress, last result, conflicts with 查看, errors, edit, stop), backup export through the system save dialog with progress and an optional media switch, restore through the system open dialog with a preview and the merge/overwrite choice, and the storage bar with cleanup actions. The assistant can open it with the sections `sync`, `backup` and `storage`.
