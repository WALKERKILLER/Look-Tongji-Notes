## Contract

Each device keeps its working library, SQLite index, credentials and runtime private. A folder transport publishes only explicitly selected course trees, course-scoped assistant history and portable personal state. A versioned marker identifies the portable library. Immutable SHA-256 objects and separate device manifests prevent a file transfer racing its manifest from installing incorrect bytes. A missing or corrupt object leaves the local copy intact and is retried. Unknown versions are rejected before import. Vector clocks detect edits made independently. For `study-canvas.json`, the latest saved whole document is selected automatically: causally newer saves win, concurrent saves compare file modification time, and equal times use a stable hash tie-break. Losing canvases remain recoverable under `.sync-trash`, without blocking conflict prompts. Other conflicting content retains the existing manual review flow. Deletions retain a recoverable copy. Device clocks must be accurate for concurrent offline save ordering.

Disabling a course or media excludes it from publication but retains its local vector-clock baseline, so edits made while excluded remain detectable when it is enabled again. Concurrent additions to a course's session index merge by session ID; an existing ID keeps the selected version's metadata, subject to ownership validation. Synthesized record unions advance the receiving device's clock. Equal clocks with different content use deterministic conflict selection rather than manifest enumeration order. Replaying an already applied bookmark deletion does not report another state change.

Portable playback, bookmarks and activity are merged in one SQLite transaction per received device state. A bookmark's stable ID cannot change its lecture ownership. Activity must have a valid day, kind and bounded totals, and any lecture ID must belong to the claimed selected course. Invalid selected-course state rolls back that state merge; unselected-course records are ignored. Activity totals merge by maximum and signal a refresh only when a stored value grows or a bucket is added.

Before applying a generation, course directory mappings must target a nonexistent directory or a directory whose `course.json` has the same course ID. A missing marker in an existing directory is also accepted when the private baseline records that exact course-to-directory mapping and a previously tracked marker; this lets an already synchronized deletion finish on subsequent rounds. A legacy baseline acquires this mapping during a successful round while its marker is present. A legacy directory already missing its marker requires recovery rather than guessing ownership. Global quiz destinations and assistant session IDs retain their existing course ownership, including deletions; unclassified chats cannot be claimed by incoming course metadata. Assistant export matches the session header ID, not a substring of its filename, and scans headers once per export round rather than once per selected course. A same-course rename is accepted when the same generation contains the old path’s tombstone and exactly one live replacement. `sessions-meta.json` is authoritative for existing local session ownership; per-course export caches cannot undo local reassignment and empty selected-course exports are removed. Releasing a locally reassigned session from its old course preserves the global file. Malformed global quiz/session files outside the selected or previously tracked scope are left untouched; a malformed tracked file stops publication with its path in the error. All destination ownership checks complete before the first working-file replacement.

Each folder object is limited to 4 GiB, and a receive generation may stage at most 8 GiB of unique objects, including objects needed for conflicting versions. This is a staging limit only: installed working files, `.sync-conflicts` and `.sync-trash` copies consume additional space and can make peak disk use exceed 8 GiB. Negative sizes, invalid hashes and inconsistent sizes for the same hash are rejected before opening objects. A record merge reads at most 32 MiB across all versions; larger histories retain file-level conflict handling. Exceeding a receive limit leaves working files unchanged and reports an error; select fewer courses or disable media to reduce a generation. Local scan and hashing errors, including an unavailable configured root, stop publication; unreadable files are not published as deletions. These bounds limit temporary work, not total library size, and do not guarantee that a device has enough free disk space. Metadata documents are bounded to 32 MiB. Private indexes must be JSON objects; null session entries are rejected. Invalid indexes stop publication instead of representing an empty collection. Server-owned index writes use a temporary file and replacement rename; this avoids truncated JSON but does not serialize another process’s read-modify-write operation.

Folder sync retains the identity of both working roots during a round and checks it before apply and publication; a missing or replaced root stops the round. Cancellation is checked before apply and between destinations. Every destination scheduled for replacement is compared with its scanned hash before the first replacement, and checked again before its own write. This is not a multi-file filesystem transaction: a later I/O failure can leave earlier verified files installed. Such an apply reports a partial result and refreshes the index for installed files when the original roots remain available. An unreadable local baseline stops publication rather than resetting history. Exchange manifests are limited to 32 MiB on read and publication; oversized input is rejected rather than truncated.

Manual conflict restoration uses the same selected-course and destination-ownership checks as automatic import. Folder recovery copies require an active folder configuration with the course selected; disconnecting cannot bypass these guards. The current-content hash is checked inside the library write lock; a stale preview refuses replacement. The current file is backed up before restoration. A successfully restored working file triggers index and UI refresh even if writing the resolution acknowledgement fails; that failure remains visible and the recovery source remains available.

The folder bridge checks every five seconds and coalesces local saves for two seconds. Received changes refresh relevant screens. The open canvas independently checks its current saved document every five seconds while visible and when returning to the foreground, so a lost push notification cannot leave it stale. A clean canvas adopts the received document automatically. An unfinished local stroke or pending local edit completes its automatic save against the current revision, becoming the newer whole document; revision races retry at most twice. Legacy crash drafts remain recoverable. Replaced saved canvases retain recovery copies. This is whole-document replacement, so a later saved layout can supersede earlier handwriting; objects and strokes are not merged. Status distinguishes local publication from cross-device delivery. Android uses a persisted system directory grant and a bounded native HTTP storage bridge; arbitrary host paths are not exposed. WebDAV retains its existing behavior and cannot run concurrently with folder sync for the same local configuration.

Desktop folder publication uses replacement rename; a failed rename does not remove its existing target. Android SAF publication retains the old document under a unique `.previous-…` name until the new document is renamed into place. A failed rename attempts to restore the old name; if the provider also refuses restoration, the old document remains as a recovery copy. Failure to remove a backup does not invalidate an installed new document, and a disconnected HTTP client cannot trigger deletion of a successfully published document. Provider operations are not a filesystem transaction; recovery copies and actual device interruption behavior must be checked during native acceptance.

## Verification

Exercise isolated libraries and one transport, including all six three-device publication orders for offline edits and delete/edit races: initial transfer, hash failure, missing objects, independent edits, conflicts, deletions, bookmarks and progress, path escapes, scope exclusions, unknown versions and restart. Test Android directory cancellation/revocation, legacy client drafts, automatic whole-canvas replacement and bounded revision retries. Verify six real lectures and all media/material hashes on NAS; require actual device evidence for each platform's acceptance.

The following matrix identifies the primary automated evidence and its limits; passing a package test does not establish native release acceptance.

| Invariant | Primary evidence | Limit |
|---|---|---|
| Selected scope, ownership, unreadable inputs and course deletion lifecycle | [Folder lifecycle tests](../../lookd/internal/datasync/folder_lifecycle_test.go) and [validation tests](../../lookd/internal/datasync/folder_validation_test.go) | Private-baseline migration requires an intact marker for its initial ownership record |

| Native storage publication preserves a previous document on rename failure | [Android publication tests](../../app/android/app/src/test/kotlin/cn/lookstudio/look_studio/FolderDocumentPublicationTest.kt) | JVM provider model; hardware revocation, power loss and transfer interruption require native acceptance |

Concurrent Go/Node writes to the global assistant session index are a known release blocker. Each process can read an old snapshot and replace the other process’s additions; atomic file replacement and Go’s race detector do not prevent this. The [review-coverage postmortem](../postmortems/0001-folder-sync-review-coverage.md) records the deterministic reproduction. Assistant history synchronization must not be accepted until a shared writer protocol and a cross-process regression protect both updates. Error propagation and retry after a failed session-index merge also need verification through the running assistant. Hard termination, disk exhaustion, Windows path semantics and current native packages remain outside this automated evidence.
