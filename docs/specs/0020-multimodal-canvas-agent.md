# Multimodal canvas agent and drawing controls

Artifact-Version: 1
Status: Approved
Approved-By: local deployment owner (upstream maintainer review pending), explicit chat approval on 2026-10-29

The conversation-only tool boundary in [spec 0021](0021-modular-canvas-conversations.md) takes precedence over the operation-producing behavior recorded here. This is the historical local implementation contract, not upstream maintainer approval.

## Intent

Extend the existing Flutter study canvas into a workspace that exposes task-relevant document, video, image, text and selected ink context to the existing model pipeline, and accepts bounded, editable, source-linked knowledge objects from a model tool loop. Preserve native playback, incremental ink rendering, the coordinate system, per-lecture storage and undo/redo. Implement the drawing controls the owner requested, using independently implemented controls informed by the inspected Notein APK; do not copy proprietary code or artwork or claim unverified feature parity.

The owner requested this scope in chat on 2026-10-29. This contract amends the no-agent-canvas-write scope of [0019](0019-lecture-study-canvas.md) only for user-triggered canvas runs. Existing chat tools, note-overwrite guards, transcript coverage guards, resident memory and applied-action permissions retain their own contracts.

## Contract

Canvas context contains workspace/lecture identity, focused and explicitly selected object identifiers, selected text ranges, selected world/normalized object regions, selected stroke identifiers, current video time or an explicit interval, source anchors, availability and bounded excerpts. A reviewable context picker appears before inference and lets the user remove sources, include nearby lecture transcript and authorize visual attachments. Hidden layers and unselected material are excluded. When nothing is selected, explain the default current-video context rather than silently reading all canvas cards.

Document text comes from the imported PDF page's extracted text or the text card's actual content. Text anchors record the stable document/object identity, page and UTF-16 range, with a source fingerprint; region anchors use normalized object coordinates and selected stroke identifiers. Selection is real UI selection; no generated sample text substitutes for extraction. Scanned pages without text are labeled as requiring vision. Visual context is captured only for a selected, bounded region or selected image and includes the original region coordinates. Visual model or image capability absence is an explicit unavailable result, never a guessed interpretation.

Lecture video context uses the existing timestamped transcript around the current time or requested interval. Read and return only bounded relevant segments, with original timestamps. Existing ASR/download jobs remain user-triggered and their results are reused; missing transcript exposes the existing transcription action. Local imported videos expose their actual playback time and availability. Frames are optional and only used when actually readable; unsupported frames, remote media and missing ffmpeg degrade explicitly to available text/time context. Do not upload entire video files or automatically start full-course transcription.

Reuse the configured ModelPipeline and its image-capable or dedicated vision-model path. A dedicated canvas-run endpoint executes a bounded tool loop scoped to the submitted, reviewed context; it does not grant the general bot new library or filesystem permissions. The model can call get_canvas_context, read_document_selection, get_video_context and inspect_canvas_region, then create_note_card, create_explanation_card, create_knowledge_card, create_practice_card, create_connection, update_canvas_card and focus_source. Tools may be combined or renamed to match the existing SDK. Resource identifiers resolve only within the approved run context; arbitrary filesystem paths, library traversal, remote image URLs, executable code and unbounded canvas replacement are rejected.

Tool creation stages typed operations and reports their status in the run. A successful run applies validated new objects together through one existing document undo checkpoint; cancellation, failure, stale document edits or invalid results apply no partial batch. Updating existing content always presents a concrete preview and requires a user click before application. Tools cannot delete original source material or modify locked/hidden layers. Runs have cancellation, deadlines, capped tools/objects/text/images, busy/error states, a visible tool trace and an explicit retry path. Raw source text, image bytes and model keys are not written to diagnostic logs.

Generated objects contain typed blocks for headings, explanations, lists, steps, comparisons, code/math and practice prompts/hints/answers, plus source anchors and generation identity. They render through existing safe Flutter widgets, remain editable/movable/resizable/deletable, and persist with the document. Connections are first-class persisted relations between object identifiers with an editable label; deleting a card removes its dangling relations through the same undo transaction. The model cannot execute JavaScript/HTML. Unknown source references are rejected. An anchor click seeks a video, focuses the original page and selected region, or focuses the ink selection. Changed or missing source text is reported as stale rather than silently retargeted.

Continue requests can target selected generated cards and their existing source anchors. New objects are placed near the current viewport using bounded collision-aware placement. The original materials stay in place. A batch is undoable and redoable and its references survive a close/reopen. Additive document fields preserve existing version-1 documents; unsupported new fields are not silently dropped by the current server/client pair. Validation runs in both the model tool boundary and the persisted library boundary.

Drawing controls include a compact Notein-inspired pen dock, pen/highlighter families, reusable presets, width presets and continuous width, color palettes and custom hex colors, opacity, pressure response, smoothing, eraser size and partial/whole-stroke mode. Settings persist locally and are recorded per stroke where they affect replay. The visible preview uses the same renderer as actual ink. Existing completed/live stroke separation and bounded chunking remain. Existing strokes retain their appearance; unsupported proprietary effects or vendor prediction are documented rather than represented by nonfunctional toggles. Pen/eraser touch handling, palm rejection and drawing shortcuts remain available.

Do not replace the installed application, publish a release, commit or push. Produce a separate macOS test app/DMG after available tests. A real configured model is required for a real inference acceptance result; an absent key is reported with reproducible configuration/test instructions. Protocol fixtures may test tool mechanics but are explicitly identified as fixtures and never counted as successful model understanding.

## Plan

Audit the canvas model/render/input/storage and the existing player/ASR/model pipeline. Extend the source and selection model, expose bounded context adapters and the dedicated model tool loop, integrate typed object rendering and application/preview, then add source navigation and drawing controls. Update the Flutter and Node clients together with server API changes. Retain the pinned native staging/packaging seam and record the tool-scope decision separately.

## Verification

Model tests cover stable page/range/region/time anchors, context filtering, selected ink, typed block round trips, layout, connections, editing, batch undo/redo and brush-setting replay. Node tests use an explicit model-protocol fixture to verify actual tool selection/execution, allowed source resolution, invalid operations, cancellation, limits and image fallback without claiming real inference. Go tests exercise persistence, new-field validation, rooted media access, document conflicts and imported PDF metadata. Run relevant existing tests and governance gates; keep any independently reproduced pre-existing failure distinct.

Exercise four UI workflows with synthetic but real PDF/text/image/video/ink assets: PDF selection to cited editable explanation and source navigation; paused-video transcript plus PDF selection with two anchors; bounded selected ink/visual region with real image input or explicit model-unavailable state; multiple knowledge cards/connections with edit/move/undo/reopen. Record separately which flows reached a real configured provider, which only reached protocol fixtures, and which are blocked. Verify brush controls affect stored/replayed strokes and long strokes remain bounded. Package, mount and verify the separate DMG and code signature.

## Evidence

The existing implementation seam is documented in [study-canvas.md](../study-canvas.md). The local deployment owner approved this contract in chat on 2026-10-29. The Flutter context picker, bounded Go extraction route, dedicated Node tools, structured cards/connections/source navigation, drawing controls and separate native package are implemented. Go race tests cover real imports and selection/interval filtering; Node protocol tests cover the actual tool loop, unavailable vision, cancellation, budgets and error redaction; Flutter tests cover batch persistence/undo, actual brush pixels, selected ink PNG capture, settings and response restoration. The brush-preview pixel regression was confirmed to fail with the unbounded background fill and pass with clipped painting. A packaged-daemon smoke test imported a real two-page PDF with PDFKit, checked its exact text selection plus timestamped transcript context, round-tripped structured sources/connections/responses, and received the real host’s explicit missing-model error. No real model was configured in the isolated fixture, so the four workflows’ real inference acceptance remains pending; protocol fixtures are not counted as successful multimodal reasoning. Native visual inspection confirms the canvas, PDF and pen settings; the macOS accessibility tree loses modal descendants, which limits automated native interaction. Reproducible model-backed steps are in the [Demo tutorial](../tutorials/canvas-agent-demo.md).
