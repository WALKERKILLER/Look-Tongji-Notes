# Look Studio — overview

A Material 3 desktop/mobile client for Tongji's lecture-recording platform (look.tongji.edu.cn), built on the Look-Tongji-Notes skill.

## Architecture

```
app/    Flutter UI (MD3, media_kit player, gpt_markdown streaming rendering)
  └─ starts lookd and talks to it over 127.0.0.1 + token
lookd/  Go daemon: IAM login and auto-renewal, Look API, segmented downloader, transcription, SQLite index, SSE events
  └─ supervises agent/
agent/  Node.js host for the embedded Pi Agent (@earendil-works/pi-coding-agent SDK), exposed under /agent/*
```

- Login: plain-HTTP IAM SSO, no browser needed. The JWT is renewed at about 80% of its lifetime: silent SSO first, then the password sealed with AES-GCM on this machine.
- Downloads: preallocated `.part` file, multiple connections with work stealing, resume from checkpoint, automatic re-signing on 401/403/410, and a global speed limit. A job that fails for a transient reason (network errors, stalls, HTTP 408/429/5xx) goes back to the queue after 15 s, 30 s, 1, 2, 5 and 10 minutes, so a batch carries on by itself when the connection returns; queuing a paused or failed lecture again keeps its progress. The 下载 page pauses, resumes or retries every job at once (`POST /api/jobs/bulk {action, ids?}`).
- The assistant has two kinds: the resident bot and conversations (会话), switched by a segmented button in the panel. Conversations read courses, transcripts, notes and courseware and offer clickable action buttons; a course agent (课程助手 on the course page, or 新会话 on a course or lecture) stays within its course. Conversations write only notes, schedule marks, outlines and quizzes. Only a small core tool set is declared up front; `find_tools` loads the other groups (course, notes, schedule, outline, courseware, help) on demand. Each turn is capped at 24 tool calls, and tool results at 16 000 characters.
- Notes: when asked to write lecture notes the assistant loads the notes toolkit, which returns a playbook: read the whole transcript first (saving a lecture note is refused while more than 10% of it is unread), collect key points and uncertain spots, look at the slides on screen at those moments (`view_slides`), search and read the parsed courseware and its figures (`search_courseware`, `view_images`), then save a new note. It never overwrites the user's own notes, and replaces one of its own only with `replace: true` when the user asked for it. Images go straight to a chat model that accepts them; for text-only models a vision model chosen in 设置 → 助手 → 识图模型 transcribes them (cached by image hash in `agent/vision-cache.json`). lookd serves any slide at `/api/lectures/{id}/slides/{idx}/image` (downloaded file or the platform image) and searches courseware at `/api/lectures/{id}/courseware/search`.
- Reading: notes open in a reader with contents (tracks the section being read), reading progress and in-document search; timestamps, `look://slide/…` and `look://courseware/…` references open the recording moment (slide on screen plus transcript), the slide or the courseware passage in a supporting pane (a bottom sheet on narrow windows); `look://lecture/<id>` without a time opens the lecture in the player, `look://file/…` opens a library image in the viewer or another file in the system's app, web links open in the browser, and a link the app cannot open says so. Parsed courseware uses the same reader. Markdown everywhere goes through one renderer (`app/lib/widgets/look_markdown.dart`): `$…$`, `$$…$$`, `\(…\)`, `\[…\]`, bare `\begin{aligned}` blocks and `$ x $` are normalized outside code, inline math is set at text size, wide display math scrolls.
- Bot: one resident assistant with a name, a mascot (a shape with two capsule eyes whose moods follow what it is doing; 8 shapes, palette colours) and Markdown memory files under `agent/bot/memory/` (关于你, 偏好, 做法, 课程, 笔记). Its prompt carries 关于你 and 偏好 in full and an index of the rest; two minutes after a conversation (or after six turns) a background run consolidates new facts and routines into the files, without deleting, and refuses passwords, ID, card and phone numbers and keys. It operates the app: opens pages, controls the player, changes appearance and player settings, pins, hides, renames and colours courses, pauses, resumes and retries downloads at once with 撤销; downloads, file deletion, download, transcription and model settings, scheduled tasks and plugin switches appear as cards that run only when applied. The bot page (tap the mascot) edits identity, persona and memory and lists consolidation runs. Contract in [spec 0007](specs/0007-resident-bot-and-course-agents.md).
- Schedule (日程): homework, exams, activities, deadlines and to-dos with a month calendar and an agenda. The assistant's `mark_schedule` only creates an item when the source states a date, and the quoted words must be found in the transcript (near the given time), the user's message, courseware or a note. Agent marks are deduplicated by title, date and course. Items are stored in the `schedule` table and mirrored to `<library>/schedule.json`; marks with a time show up in the transcript and as dots on the seek bar.
- Outline (大纲): the assistant splits a lecture into chapters (`POST /agent/timeline`, a single model call over a digest of the transcript) in the original skill's `timeline.txt` format (`MM:SS-MM:SS：标题`). lookd normalizes the chapters (contiguous, covering the whole duration), writes `timeline.txt` and the `timeline` table, and includes `<course>_timeline.txt` in exports. The player shows chapters in a 大纲 tab, as transcript headers and as seek-bar segments.
- Courseware (课件): Look provides none, so files are uploaded per lecture (player → 资料 → 课件; PDF, Office documents and images, up to 200 MB) into `courseware/`. A `parse` job sends them to MinerU: precise API v4 (`/api/v4/file-urls/batch`, VLM or pipeline model) when a token is set, otherwise the token-free agent API (10 MB / 20 pages, no images). Results are unpacked to `courseware/<file>.parsed/` (`full.md`, `images/`). The token is sealed with the same key as the session and only its last 4 characters are ever returned; daily page usage is counted locally against the 1000-page high-priority quota (设置 → 课件解析). MinerU icon: `app/assets/brands/NOTICE`.
- Storage: Downloads → "已下载" lists files per lecture and kind and deletes them (`DELETE /api/lectures/{id}/assets/{kind}`); finished tasks can be removed with their files. With "转写完成后删除视频" (`transcript.delete_video`), the lecture's video is deleted as soon as its transcript is saved.
- Usage (设置 → 助手 → 用量与费用): every model call — chat round trips with tools, outlines, image descriptions, provider tests — is appended to `agent/usage.jsonl` (no prompt or reply text), so deleting a conversation keeps its cost history. The page shows estimated cost, tokens, calls and cache hit rate against the previous period, a daily chart (cost or stacked input / cache hit / output tokens, with a table view), rankings by model, purpose and conversation, and the call log with duration and time to first token. Costs are estimates from model prices.
- Practice (练习): the assistant writes multiple-choice sets (`create_quiz` in the `practice` tool group) only after reading the lecture, with a rationale for every option and a `look://` source per question that must point at material it read. Sets open from the chat card, the player's notes tab or 资料库 in a full-screen view (hint, per-option explanations, 讲解 to ask the assistant, 查看出处, keys 1–6 / Enter / ←→) ending with a score, per-topic results and retakes of mistakes. Sets and attempts are stored in lookd and mirrored to `quizzes/<id>.json`; finished attempts count on the heatmap.
- Scheduled tasks (rail destination 定时; on phones 设置 → 助手 or the assistant menu): a prompt with a daily, workday, weekly or one-time schedule; the agent host runs due tasks one at a time in a new conversation (`定时 · <name> · MM-DD HH:mm`) with a per-run cost cap and a 15-minute limit, only while the app runs. Missed times run once at the next start within 12 hours (catch-up) or are logged as missed. Wide windows show the task list beside its detail; a 运行记录 view lists runs of every task by day with status filters and skip reasons, the rail badge counts unseen runs, a snackbar reports each finished run, and usage is recorded with purpose `task`.
- Plugins (rail destination 插件; on phones 设置 → 插件 or the composer's "+"): packages that give the assistant new tools, playbooks and views, or add actions to notes, lectures, courses, schedule items and the composer. 发现 lists the official catalog shipped with the agent and catalogs the user adds, 已安装 manages installed plugins beside their detail; installing shows the plugin's permissions first, third-party plugins need 允许第三方插件, and each plugin has its own settings, enable switch and uninstall. Official plugins: 引导式提问 (a composer mode in which the assistant guides with one question at a time instead of giving answers). Contract in [spec 0004](specs/0004-plugin-platform.md); writing a plugin: [agent/plugins/README.md](../agent/plugins/README.md).
- Activity (主页 → 学习足迹, 统计): the app counts study minutes — watching while the player plays and the window is visible, reading a note or parsed courseware with input in the last 2 minutes while focused — and reports them to lookd every minute (`POST /api/activity`, per local day, kind and lecture). Questions to the assistant are counted; user notes created or edited and finished transcripts are derived from their own tables. Home shows a contribution-style grid of recent weeks with this week's time and streaks; 学习统计 shows a year with per-kind and per-course totals; tapping a day lists its lectures, notes and transcripts. Nothing is recorded outside the app or for past days beyond the derived counts.
- Models: preset providers (logos from `@lobehub/icons-static-svg`, MIT, see `app/assets/providers/NOTICE`), model lists pulled from the provider's `/models`, and context/price metadata from models.dev (cached 24 h in `agent/models-dev.json`).
- Profile: nickname and avatar (emoji, generated shape, image file, image URL or QQ avatar; circle/squircle/cookie/petal outline) are device-local, kept in shared preferences with copied image files under the app support directory's `avatar/`. The home greeting shows them with a line from hitokoto.cn (一言), cached for offline use.
- Transcription: free cloud ASR over two channels, Bilibili 必剪 (bcut) and 剪映 (JianYing; protocol per VideoCaptioner, requests signed by VideoCaptioner's public signing service). Audio is cut into 20-minute chunks with 15 s overlap and spread over enabled channels (必剪 at most 2 chunks at a time, 剪映 1; requests are paced and each step retried with backoff, status polling gives up after repeated errors). A failing channel cools down (1 → 15 min for rate limits) while others take over; finished chunks are kept for 6 h so a retried job only redoes the missing ones, and a job fails with a clear message after 20 min with every channel cooling. Each channel is capped at 6 h of audio per 12 h; usage and the last 40 chunk attempts are in `asr-usage.json` and shown under 设置 → 转写 → 最近识别记录. ASR uses its own HTTP/1.1 transport, separate from the Tongji session.
- Local transcription (设置 → 转写 → 本地识别模型): a benchmark board compares six offline models (SenseVoice Small, Paraformer, Qwen3-ASR 0.6B, Fun-ASR-Nano, FireRedASR2 AED, Whisper Large v3 Turbo) by published error rate on WenetSpeech meeting audio, time for a 90-minute lecture and peak memory measured on a reference laptop. One click downloads the sherpa-onnx recogniser, Silero VAD, the model and, for models without punctuation, a punctuation model into the data directory from HF-Mirror, Hugging Face, ModelScope (where an identical copy exists) or a custom template, with resume and SHA-256 checks; the model then joins the pool as the `local` channel (no quota, one chunk at a time, configurable threads). Contract in [spec 0009](specs/0009-local-asr-models.md).
- Live refresh: lookd checks Look by itself — every 10 minutes for a lecture that just ended until its replay appears, then less often, and every 6 hours otherwise — and course pages update in place. New replays and lectures become notifications: a snackbar wherever the user is and an inbox behind the bell on the navigation rail (home header on phones). 设置 → 通知与自动刷新 switches it off or checks at once. Contract in [spec 0010](specs/0010-live-refresh.md).
- Canvas (设置 → 学校与 Canvas): choose 同济, 复旦 or another school (emblems shown), then sign in through the school's SSO (Tongji: the Look session; Fudan: UIS) or with an access token that Look Studio creates and rotates, or that the user pastes. Assignments appear in the schedule with a Canvas badge and due-soon reminders. Canvas courses link to Look courses by name (editable), and the course page shows the open assignments with tabs for all assignments, courseware (downloaded into the course folder's `Canvas/`) and announcements. New assignments and announcements become notifications; Canvas syncs every 15 minutes. Fudan iCourse replays are not connected. Contract in [spec 0011](specs/0011-canvas-and-schools.md).
- Timestamps such as `[07:58]` or `[07:58]–[10:22]` in notes and chat render as chips that seek the open player or open the lecture (`look://lecture/<id>?t=<s>` for other lectures).

## Build

Build and run instructions for each platform are in the [README](../README.md#build-from-source). ffmpeg is needed for transcription, and Node.js for the assistant. Without Node.js 22+ or the agent's dependencies the assistant panel and 设置 → 助手 → 运行环境 offer a one-click install into the data directory ([spec 0008](specs/0008-assistant-runtime-setup.md)).

## Data

| Location | Contents |
| --- | --- |
| `~/LookStudio/` | Course library: one folder per lecture (`video.mp4`, `slides/`, `courseware/` with `*.parsed/full.md`, `transcript.md/.srt`, `timeline.txt`, `lecture.json`), `notes/*.md`, `schedule.json`, `activity.json` (study-time buckets, mirrored from the index), `quizzes/<id>.json` (practice sets with attempts), a `README.md` for AI tools, and hidden working folders: `.cache/` (transcription scratch and unfinished downloads), `.mirror-journal/`, `.sync-conflicts/` and `.sync-trash/` (copies kept by sync and restore) |
| `~/LookStudio/library.db` | SQLite (WAL + FTS5 trigram) index; can be rebuilt from the files under Library → "Rebuild index from files" |
| `~/.local/share/look-studio/` | `session.json` (login state), `seal.key`, `asr-usage.json`, `asr/` (local recogniser engine and models, unless moved to a folder picked in settings: `asr/location.json`), `notifications.json`, `mineru.json` (sealed token, options, parse usage), `notion.json` (sealed integration token, parent page, synced page ids and hashes), `sync.json` (WebDAV account with the sealed password, the per-path base agreed with the remote, last result), `sync-cache.json` (file hashes by size and time), `imports/` (uploaded backups awaiting restore, removed after a day), `agent/` (model config, keys, conversations, `models-dev.json` cache, `provider-links.json`, `tasks.json` and `tasks-runs.jsonl`, `plugins.json` and `plugins/` with third-party packages and plugin storage, `sessions-meta.json` (conversation kinds), `bot/` with `bot.json`, `memory/`, `proposals.json` and `runs.jsonl`) |

Settings → 知识库 can export to the skill's `raw/<course>/<lecture>/原始数据/` layout using hard links.

Settings → 知识库 → Obsidian exports the library into a folder of an Obsidian vault as plain Markdown (one `课程库.md` index and a folder per course with `笔记/` — notes with properties plus the slides and courseware they link to — and `转写稿/`), on demand or automatically after notes change (`POST /api/library/obsidian`). Links become relative Markdown links and timestamps `lookstudio://lecture/<id>?t=<s>` deep links that open the app; files edited in the vault are never overwritten (the new version goes beside them as `(Look Studio)`). Contract: [0012-obsidian-export](specs/0012-obsidian-export.md).

Settings → 知识库 → Notion syncs the library into a Notion page the user shares with an internal integration: a `Look Studio 课程库` page with one page per course and lecture and their notes and transcripts below, on demand or about a minute after notes change (`/api/notion`). Pages edited in Notion are kept, never overwritten or trashed; timestamps stay plain text there. The integration token is sealed in `notion.json` in the data directory. Contract: [0013-notion-sync](specs/0013-notion-sync.md).

Settings → 数据与同步 syncs the library, playback positions, bookmarks and the assistant's conversations, tasks and memory between devices through a WebDAV folder (坚果云, Nextcloud, AList…), automatically or on demand, exports and restores backup zips, and shows what takes space with safe cleanup (`/api/sync`, `/api/data`, `/api/storage`). Credentials and login state stay on each device; a file changed on two devices keeps the newer edit and the other copy in the library's `.sync-conflicts/`, and files deleted elsewhere go to `.sync-trash/`. Contract: [0014-data-sync-and-backup](specs/0014-data-sync-and-backup.md).
